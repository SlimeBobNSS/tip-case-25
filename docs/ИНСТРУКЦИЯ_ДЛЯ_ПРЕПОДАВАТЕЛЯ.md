# Инструкция преподавателю: сборка и проверка

## Назначение

Проект — консольный тайм-трекер на C++17. Инструкция описывает сборку и краткую ручную проверку основных операций.

## Требования

- CMake 3.10 или новее;
- компилятор C++17;
- Windows: Visual Studio Build Tools с компонентом разработки классических приложений на C++ и Windows SDK;
- macOS: Xcode Command Line Tools и CMake.

Внешние библиотеки проекту не нужны.

## Windows

Распакуйте архив и откройте Developer PowerShell for Visual Studio в корневой папке проекта, где находятся `CMakeLists.txt` и `README.md`.

```powershell
cmake --version
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
.\build\Release\target_exec.exe .\build\demo-data
```

Программа выведет меню. Каталог `build\demo-data` будет использоваться для демонстрационных CSV-файлов. Если русские сообщения отображаются некорректно, перед запуском выполните `chcp 65001`.

Для создания ZIP-пакета выполните в PowerShell из корневой папки проекта:

```powershell
.\scripts\package.ps1
```

После распаковки ZIP запустите приложение из корня распакованного пакета:

```powershell
.\bin\target_exec.exe .\data
```

## macOS

Установите Xcode Command Line Tools:

```bash
xcode-select --install
```

Если CMake ещё не установлен и используется Homebrew:

```bash
brew install cmake
```

Проверьте инструменты и соберите проект из его корневой папки:

```bash
clang++ --version
cmake --version
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
./build/target_exec ./build/demo-data
```

Чтобы создать архив для macOS, выполните:

```bash
sh scripts/package.sh
```

После распаковки `.tar.gz` откройте Terminal в папке пакета и запустите:

```bash
./bin/target_exec ./data
```

Команда CTest запускает автоматические проверки модулей. Список проверок и их связь с критериями приёмки приведены в [плане тестирования](ПЛАН_ТЕСТИРОВАНИЯ.md).

## Краткая проверка

В меню выполните следующие действия:

1. Выберите `1`, создайте проект и запишите выданный ID.
2. Выберите `2`, введите ID проекта, создайте задачу и запишите её ID.
3. Выберите `3` и убедитесь, что проект и задача присутствуют в списке.
4. Выберите `4`, введите ID задачи и проверьте сообщение об успешном запуске таймера.
5. Выберите `6` и убедитесь, что приложение показывает активную задачу.
6. Выберите `5`, чтобы остановить таймер.
7. Выберите `7`; оставьте фильтр проекта и границы периода пустыми, нажав Enter. Завершённая сессия должна отобразиться в истории.
8. Выберите `8`, введите начало и конец периода в формате `YYYY-MM-DD HH:MM:SS`, оставьте фильтр проекта пустым и проверьте построенный отчёт. Для проверки экспорта ответьте `д` и укажите новый путь, например `build/demo-data/report-check.csv`.
9. Выберите `0`, снова запустите приложение с тем же каталогом данных и проверьте сохранённый проект и задачу через пункт `3`.

Ожидаемый результат: создаются уникальные ID, таймер запускается и останавливается, завершённая сессия появляется в истории, отчёт формирует итог, а проекты и задачи сохраняются после перезапуска. CSV-файлы хранилища находятся в переданном каталоге данных.

Эта последовательность является краткой ручной проверкой запуска. Полный набор проверок AT-01–AT-23 приведён в техническом задании и выполняется отдельно.
